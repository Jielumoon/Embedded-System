# 实验一 上板操作手册（开发环境搭建、命令行构建与在线调试）

> 适用板卡：XC-M4B3-V1.2 实验底板 + STM32F429IGT6 核心板 + ST-Link V2
> 验证工程：`lab2_1`（实验一全部阶段都在这一个工程上完成，不需要新建工程）
> 工程目录：`.\lab2_1`
> 全部命令在 **PowerShell** 里逐行执行（PowerShell 不支持 `&&`，命令要分行跑）

***

## 零、先接好三根线（其余四个实验通用）

| ST-Link V2 引脚 | 接到板子 | 说明 |
|---|---|---|
| SWDIO | PA13（丝印 SWDIO） | 数据线，接反必失败 |
| SWCLK | PA14（丝印 SWCLK） | 时钟线 |
| GND | GND | **必须接**，没共地会报 `init mode failed` |
| 3.3V | 3V3 | 板子单独供电时可省 |

先接线 → 再插 ST-Link 的 USB → 板子电源灯亮（常亮）才算通电。

## 二、阶段二：构建 → 烧录 → GDB 在线调试

### 1. 配置并构建 Debug 固件

```powershell
cd .\lab2_1
cmake --preset debug
cmake --build --preset debug
```

注意：本工程的预设名是**小写** `debug` / `release`（不是 `Debug`），写成大写会报 `No preset found`。

**成功标志**：`cmake --preset debug` 末尾出现 `Build files have been written to: .../build/Debug`；`cmake --build --preset debug` 出现 `[100%]` 或 `ninja: no work to do`。

产物在 `build\Debug\`：`lab2_1`（ELF）、`lab2_1.bin`、`lab2_1.hex`、`lab2_1.map`。

### 2. 烧录

```powershell
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg -c "program build/Debug/lab2_1.bin 0x08000000 verify reset exit"
```

**成功标志**（逐行出现）：

```
Info : STLINK V2J47S7 (API v2) VID:PID 0483:3748
Info : Target voltage: 3.2xxxxx
Info : device id = 0x20036419
Info : flash size = 1024 KiB
** Programming Finished **
** Verify Started **
** Verified OK **
shutdown command invoked
```

**预期现象**：LED1（PB1，低电平点亮）**亮 0.5 秒、灭 0.5 秒**，也就是 1Hz 稳定闪烁。

> 观察到该现象即完成实验一验收。灯不闪先看第六节排查表，不要急着重烧。

### 3. GDB 远程在线调试（开两个终端）

**终端 A** 起 OpenOCD 服务（注意这条命令**不带** `-c program`，只做调试服务器，会一直占着窗口不退出）：

```powershell
cd .\lab2_1
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg
```

看到 `Info : Listening on port 3333 for gdb connections` 就说明服务起来了。

**终端 B** 连上去调试：

```powershell
cd .\lab2_1
arm-none-eabi-gdb build\Debug\lab2_1
```

进入 `(gdb)` 提示符后依次输入：

```
target remote :3333
monitor reset halt
break main
load
continue
```

应停在 `main` 处，显示 `Breakpoint 1, main () at ...`。

单步执行（观察 LED1 电平翻转）：

```
next
next
step
```

要重来就 `continue` 跑一段，再 `Ctrl+C` 打断。

> 结束调试：在 gdb 里输入 `monitor reset run` 让板子恢复运行，再 `quit`；终端 A 里 `Ctrl+C` 关掉 OpenOCD。

## 三、阶段三：Debug 与 Release 产物体积对比

```powershell
cmake --preset release
cmake --build --preset release
```

然后比较两个 bin 大小：

```powershell
Get-Item build\Debug\lab2_1.bin, build\Release\lab2_1.bin | Select-Object Name, Length
```

本机实测：

| 配置 | 优化级别 | lab2_1.bin 体积 |
|---|---|---|
| Debug | -O0（带调试信息） | 5996 字节（5.86 KB） |
| Release | -O2 | 4376 字节（4.27 KB） |

减小约 **27%**，结论：优化级别提升后固件体积明显变小，代价是断点单步会跳行、变量可能被优化掉（所以调试必须用 Debug）。

## 四、阶段四：VS Code + clangd 图形化环境

本机现状：工程根的 `.clangd` 里 `CompilationDatabase: build/Debug` 是相对路径，只对根目录有效；真正生效要在**每个工程目录**各放一份。这一步已经补好了，`lab2_1`~`lab2_4` 目录下都有 `.clangd`，内容：

```yaml
CompileFlags:
  CompilationDatabase: build/Debug
```

生效前提是编译数据库真的存在（`CMAKE_EXPORT_COMPILE_COMMANDS=ON` 已开，构建后自动生成）：

```powershell
cd .\lab2_1
Test-Path build\Debug\compile_commands.json
```

返回 `True` 才对；返回 `False` 就重跑一次 `cmake --preset debug`。

生效判据：VS Code 打开 `lab2_1` 目录，点 `main.c`，`HAL_GPIO_WritePin` 能跳转到定义、头文件不画红波浪线（红波浪线还在就命令面板执行 `clangd: Restart language server`）。

F5 一键调试需要装两个扩展：**clangd** 和 **Cortex-Debug**。`lab2_1\.vscode\launch.json` 已写好，内容：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Cortex Debug (OpenOCD)",
      "type": "cortex-debug",
      "request": "launch",
      "servertype": "openocd",
      "cwd": "${workspaceFolder}",
      "executable": "${workspaceFolder}/build/Debug/lab2_1",
      "device": "STM32F429IGT6",
      "configFiles": [
        "interface/stlink.cfg",
        "target/stm32f4x.cfg"
      ],
      "runToEntryPoint": "main"
    }
  ]
}
```

在 VS Code 里以 `lab2_1` 目录为工作区打开，按 F5：自动起 OpenOCD、下载固件、停在 `main`。

> 没装 Cortex-Debug 扩展时 F5 会报 `configured debug type "cortex-debug" is not supported`，装完重开窗口即可。
> 本机目前没有 SVD 文件，所以 `launch.json` 里故意没写 `svdFile`；等第五节路线 B 的 SVD 下好了，再加一行 `"svdFile": "${workspaceFolder}/svd/STM32F429.svd"`，左侧就会多出外设寄存器树。

## 五、阶段五：观察 GPIOB 寄存器随 LED1 翻转

两条路，任选其一，都算完成阶段五。

### 路线 A（不需要额外文件，现在就能做）

在阶段二的 gdb 会话里，跑到 `HAL_GPIO_WritePin` 附近单步，然后读寄存器：

```
p/x *(unsigned int *)0x40020400
p/x *(unsigned int *)0x40020414
```

- `0x40020400` = `GPIOB->MODER`：bit[3:2] 为 `01` 表示 PB1 是通用输出模式。
- `0x40020414` = `GPIOB->ODR`：bit1 = 0 表示 LED1 亮（低电平点亮），bit1 = 1 表示灭。

连续 `next` 两次（一次 `HAL_GPIO_WritePin(..., GPIO_PIN_RESET)`、一次 `...SET`），ODR 的 bit1 会在 `0x0` 和 `0x2` 之间来回变，这就是“寄存器随 LED 翻转”。

### 路线 B（挂 SVD，图形化看）

本机仓库里**没有** `svd\STM32F429.svd`，需要自己下载一份放到 `lab2_1\svd\STM32F429.svd`（ST 官网 SVD 包或 Keil 的 `STM32F429_DFP` pack 里都有），再在 `lab2_1\.vscode\launch.json` 的配置对象里补一行：

```json
"svdFile": "${workspaceFolder}/svd/STM32F429.svd"
```

F5 调试时左侧 `XPERIPHERALS` 树里展开 `GPIOB`，单步看 `MODER`、`ODR` 数值变化即可。

## 六、故障排查速查表

| 现象 | 原因 | 处理 |
|---|---|---|
| `Error: open failed` / 找不到 ST-Link | STSW-LINK009 驱动没装、USB 接触不良 | 设备管理器确认有 `STM32 ST-LINK`，重插 USB |
| `Error: init mode failed (unable to connect to the target)` | SWD 线接反 / 没共地 / 板子没供电 | 核对 SWDIO→PA13、SWCLK→PA14，GND 必接；这一步和下载成功前的 `Target voltage` 出现与否无关，电压有值也可能连不上目标 |
| `No preset found` | 预设名大小写写错 | 用 `--preset debug` / `--preset release`（全小写） |
| `cmake --preset debug` 报宏定义缺失 / 头文件找不到 | 缓存脏或器件宏没传 | 删掉 `build` 目录重新 `cmake --preset debug`；工程已内置 `-DSTM32F429xx -DUSE_HAL_DRIVER` |
| 烧录成功但 LED1 不闪 | 烧错 bin / 进入了 HardFault / 旧链接脚本栈顶越界或 `_init` 被 GC / 板子晶振不是 25MHz | 先确认烧的是修正后的 `build\Debug\lab2_1.bin`（初始 SP 应为 `0x20030000`），且链接脚本含 `KEEP(*(.init))`/`KEEP(*(.fini))`；再重新上电复位 |
| 烧录成功但上电即死 | HSE 25MHz 起振失败 | 检查核心板晶振，代码按 25MHz 配置 |
| `:3333` 连接被拒 | OpenOCD 没起来 / 上次残留进程占用端口 | 终端 A 先看到 `Listening on port 3333`；必要时 `Get-Process openocd | Stop-Process` |
| gdb 里 `load` 后仍停在旧程序 | 没 reset | 先 `monitor reset halt` 再 `load` |
